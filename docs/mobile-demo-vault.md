# csvzall Lite demo vault

The generated repository's `demo-vault/` is the desktop and mobile test bed for
csvzall Lite. Its plugin ID remains `csvzall-mobile`, and its repository remains
`obsidian-csvzall-mobile` so existing installations keep their identity.
Its fixtures come from `mobile-demo-vault/` in the source repository and include
the desktop demo's Productivity Tracker.csv plus mobile-specific cases.
Edit fixtures and setup tooling in the source repository, then regenerate.

## Prepare from the source checkout

```sh
npm run test:mobile
npm run sync:mobile-repo
```

Sync builds and validates the mobile plugin, updates the generated repository,
and installs the three plugin artifacts in
`../obsidian-csvzall-mobile/demo-vault/.obsidian/plugins/csvzall-mobile/`.
The vault uses ordinary files so it can be copied to a device. No symlinks,
desktop helper, or native binary is needed. Existing fixture edits, extra
files, workspace state, and vault-local plugin settings survive a refresh.
Setup defaults Obsidian's **Show all file types** option (`showUnsupportedFiles`)
to enabled so CSVs are visible even before the mobile plugin loads. Existing
explicit visibility preferences and other app settings are preserved.

To install an already-built distribution into another disposable test vault:

```sh
node scripts/setup-mobile-demo-vault.mjs --vault /absolute/path/to/mobile-test-vault
```

From a clean generated mobile checkout, run
`node scripts/setup-mobile-demo-vault.mjs` to install its checked-in build into
its own demo vault. Rerun after updating the checkout. It refuses symlinks and
junctions in the target paths. Fixture files are seeded only when absent;
refreshes replace only the three installed plugin artifacts and add the mobile
plugin to the enabled-plugin list while preserving other enabled plugins.

## Test on desktop

Open `../obsidian-csvzall-mobile/demo-vault` as a vault in desktop Obsidian and
enable csvzall Lite. Keep the native csvzall plugin disabled in this vault
because both plugins register the CSV extension. The bundled viewer supports
basic viewing and editing on desktop without a helper binary.

After a source change, run `npm run sync:mobile-repo`, then disable and re-enable
csvzall Lite or reload Obsidian. Reopen the CSV pane. Test editing, saving,
new-file creation, unsaved changes, navigation, and live theme changes here.
The same build runs on phones and tablets.

The desktop smoke test for 0.1.3 used Obsidian 1.14.4 on Windows: the bundled
grid loaded, a cell was edited and saved to the vault, and the saved value
survived navigating away and reopening the CSV. Source refresh validation passed
31 upstream viewer tests, 140 desktop/helper tests, and 11 mobile/setup tests.
Desktop integration includes Blob document/script URLs and an embedded worker
build that does not misidentify Electron's browser worker as a Node runtime.

## Test on a device

Copy the entire `demo-vault` folder, **including hidden `.obsidian` files**, to a
device-accessible folder or an existing vault-sync workflow. Open that folder
as a vault in Obsidian mobile, enable community plugins if prompted, and enable
csvzall Lite. Start with `Start here.md` and its checklist.
If CSV files are hidden, enable **Settings → Files and links → Show all file
types** (called **Detect all file extensions** in older Obsidian versions).
After refreshing the build, transfer the three plugin artifacts again and reload the plugin or
restart Obsidian. Extracted WASM files are regenerated by the plugin.

Desktop testing covers the shared WASM viewer and vault read/write bridge.
Android keyboard behavior, touch navigation, and device-specific WebView behavior
still need device checks before release. Record the device,
OS, Obsidian version, and results when running the checklist.

Fixture files are version controlled; `.obsidian/`, settings, installed builds,
extracted assets, and workspace state remain ignored. Use a disposable copy for
destructive checks. Never import private vault content or machine settings.
